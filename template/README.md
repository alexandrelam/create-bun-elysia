# __APP_NAME__

Bun monorepo with an Elysia + Drizzle (SQLite) API, Better Auth (Google sign-in) and a React (Vite) frontend.

```
apps/
  api/   Elysia server, Drizzle ORM on bun:sqlite, Better Auth → http://localhost:3000/api
  web/   React + Vite, typed client via Eden Treaty           → http://localhost:5173
packages/  (optional) shared workspace packages
```

## Commands (run from the root)

| Command                                | What it does                                              |
| -------------------------------------- | --------------------------------------------------------- |
| `bun dev`                              | Run API (watch mode) and web (Vite HMR) together          |
| `bun run build`                        | Build both apps                                           |
| `bun run typecheck`                    | Type-check both apps                                      |
| `bun run check`                        | Lint (oxlint, strict) + format check (Prettier) + typecheck |
| `bun run lint:fix` / `bun run format`  | Auto-fix lint issues / format everything                  |
| `bun run db:generate`                  | Generate a SQL migration after editing the schema         |
| `bun run db:migrate`                   | Apply migrations (also runs automatically on API start)   |
| `bun run auth:generate`                | Regenerate Better Auth tables after adding an auth plugin |

Every commit runs a Husky pre-commit hook: oxlint and Prettier on the staged files, then a
full typecheck. A lint or type error blocks the commit.

## Google sign-in setup

1. In the [Google Cloud console](https://console.cloud.google.com/apis/credentials), create an
   **OAuth client ID** of type **Web application**.
2. Add the authorized redirect URI `http://localhost:5173/api/auth/callback/google`.
3. Put the client ID and secret in `apps/api/.env`:
   ```
   GOOGLE_CLIENT_ID=...
   GOOGLE_CLIENT_SECRET=...
   ```
4. Restart `bun dev`.

`BETTER_AUTH_SECRET` was generated for you when the project was created. `BETTER_AUTH_URL` is the
URL the browser uses (the Vite dev server, which proxies `/api` to the API). In production, set it
to your public URL and add the matching redirect URI in Google.

## Code layout

Code is grouped by feature (`auth/`, `todos/`), with global setup in `shared/`. Each module is
imported only through its `index.ts`, and lint rejects deep imports like `../auth/client`. See
[CLAUDE.md](CLAUDE.md#code-organization) for the rules and how to add a feature.

## Auth in the API

The `auth` module (`apps/api/src/auth/`) configures Better Auth, serves its endpoints under
`/api/auth/*`, and exports `authPlugin`, which adds an `auth` route option:

```ts
import { authPlugin } from "../auth";

new Elysia({ prefix: "/me" })
  .use(authPlugin)
  .get("/", ({ user }) => user, { auth: true }); // 401 when signed out
```

Use `.guard({ auth: true })` to protect every route in a plugin, as the `todos` module does.
Todos belong to the signed-in user.

In the web app, the `auth` module (`apps/web/src/auth/`) exports `useSession`, `SignIn` and `UserMenu`.

## Database workflow

1. Edit a file in `apps/api/src/shared/db/schema/` (`auth.ts` is generated by Better Auth: don't edit it by hand)
2. `bun run db:generate` writes a new migration to `apps/api/drizzle/`
3. Restart the API (or `bun run db:migrate`). Migrations are applied on startup.

The SQLite file lives at `apps/api/data/app.db` (override with `DATABASE_URL` in `apps/api/.env`).

## Deploy

Pushing to `main` deploys to your server with GitHub Actions + Docker Compose. In production
the API container also serves the built React app. One-time setup (server, env, HTTPS, GitHub
secrets): [.github/workflows/README-deploy.md](.github/workflows/README-deploy.md).

## End-to-end types

`apps/api/src/index.ts` exports `type App`. The web app imports it in `src/shared/api/` and uses
Eden Treaty, so API routes, params and responses are typed in the frontend with no codegen.
